> **Amended by ADR-0022** (ticket #15): `rewindStep` now also supports an `inclusive` mode
> in which the target step itself is undone along with everything after it — that is how the
> offered "undo this build" action after a failed plan works. Without the flag, everything
> below holds verbatim, including "the target step itself is left untouched".

# Rewind discards every step after the target within its own plan, by reverting each Artifact's real App change and resetting the Step row to pending

Ticket #7 asks the user to "rewind" a completed plan to an earlier step: everything the plan built after that point should disappear from the App, not just from the chat transcript. A `Step`'s `messageId` already ties it to the one `approvePrd` call that created it (ADR-0004), and `Step.order` already gives a plan its execution order — so "the current plan's execution" and "every step after the rewind target" are both direct queries on existing columns: `steps` where `conversationId` and `messageId` match the target step's, and `order > target.order`. No new column or concept is needed to satisfy "does not affect steps from a separately approved PRD" — a later `approvePrd` call always produces Steps under a new `messageId` (a fresh PRD-approval message), so they're already disjoint from an earlier plan's Steps by construction.

Undoing a Step means reverting the real App/DB change its Artifact made, not just deleting rows: a `CreateTable` Artifact's `content.table_name` maps straight onto `TooljetDbTableOperationsService`'s `drop_table` action; a `CreateQuery` Artifact's `content.id` maps onto `DataQueryRepository`'s delete path; a `CreateComponent` Artifact's `content.id` maps onto `ComponentsService.delete` (widgets) or `PageService.deletePage` (pages, distinguished the same way `executeComponentStep`'s pageId-hallucination check already distinguishes them — a Page artifact has no `pageId` field of its own, every widget's does). A Form artifact additionally carries `queryId` for the insert query ADR-0007 created alongside it — undoing a Form deletes that query first, then the Form component itself (its submit `EventHandler` is already cascade-deleted by `ComponentsService.delete`, the same cascade `createFormComponent`'s wiring relies on being reversible).

Steps after the target are undone in **reverse order** (highest `order` first), not plan order — a later step can reference an earlier one's output (a Form's `tableId`, a Table widget's `queryName`), never the reverse, so undoing back-to-front means every dependency a step's Artifact might still need has already been removed before the step that depends on it, in the same order `TooljetDbTableOperationsService.dropTable`'s own "table still in use by a query" check would otherwise reject if done forward.

Each undone Step's row is not deleted — its `status` is reset to `'pending'`, `artifactId`/`errorMessage` cleared, `attempts` reset to 0 — matching Step's existing pre-execution shape (`generateStepPlan`'s initial insert) so the row accurately reflects "not yet built" rather than lingering as `'succeeded'` with a dangling `artifactId` pointing at a Artifact that no longer exists. The Artifact row itself is deleted, matching the acceptance criterion's literal "discards the Artifacts." The target step itself (the one the user rewound *to*) is left untouched — rewind takes the plan back to the state right after that step finished, not before it.

If reverting a Step's real App change throws (e.g. a table somehow still has a live foreign-key reference an in-plan query didn't cover), the whole rewind fails and no Step/Artifact rows for the failed step or anything after it are touched — reported as-is to the caller. A partial rewind (some later steps successfully undone, then a hard failure) is a real, if rare, possible outcome; the alternative of silently marking a step "rewound" whose App change might still be live would leave the App and the Step ledger disagreeing about what actually exists, which is worse than surfacing the error and leaving the ledger in its last-known-true state.
